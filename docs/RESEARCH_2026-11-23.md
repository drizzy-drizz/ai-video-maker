# Research dossier — general AI episodic video creation
_2026-11-23 | primary-source baseline. Recheck model terms before each bundled release._

## Goal and product constraints
Users paste **their own storyline** (not necessarily a prompt), choose Filipino/Tagalog or English, and make a multi-episode series across **any genre**. Editable canon persists: named characters, places, wardrobe, voices, visual references, events and chronology. The app must distinguish *film planning*, *real generated motion video*, and *editorial fallback*; no misleading "AI video completed" when output is a still-image slideshow.

No required paid API, subscription, quota bypass, or hosted inference. Downloadable weights can be free, but real local video generation needs considerable compute, disk space, and electricity. Never promise unlimited, instant high-quality video on a Ryzen 5 5600G APU / 16 GB RAM.

## Google Flow benchmark — what to reproduce, not imitate
Official documentation:
- [Product overview](https://labs.google/fx/tools/flow): creative studio, reusable ingredients, scenebuilder, extension.
- [Create videos](https://support.google.com/flow/answer/16353334?hl=en): text / image / ingredients, first-last frames, character references.
- [Edit and build scenes](https://support.google.com/flow/answer/16935718?hl=en): stitch scenes, extend shots, references.
- [Free access and credits](https://support.google.com/flow/answer/16353333?hl=en): no-subscription basic access; 50 credits/day (as checked on 2026-11-23); advanced features require paid tiers.
Competitive lesson: the advantage is the shot-to-scene pipeline, persistence and continuity controls; it is NOT one large text-to-video request. Flow's proprietary Veo/Omni generation models and results are not magically replicated by open weights.

### Feature inventory (targets)
1. Project/series library and editable story source; reversible revisions and backups.
2. Story analysis: protagonist, conflict, beats, canon, locations, timeline, budget, safety/copyright flags.
3. Episode outlines (unbounded count determined by story), recap, cliffhanger, continuity checks.
4. Shot storyboard: actor/subject, action, camera, blocking, framing, lens, lighting, environment, negative prompt, shot duration.
5. Reusable "ingredients": character sheet + reference images, settings, props, look bible; prompts reuse IDs and version pins.
6. Multi-model local adapters for text-to-video, image-to-video, video-to-video and first-last frames.
7. Asset/bin, clip versions, seed reproducibility, alternatives, retake, inpainting and outpainting when models support them.
8. Non-destructive unified timeline: clips, sound effects, TTS/narration, music, captions, transitions, camera moves, source provenance.
9. Narration by locale, character-specific speakers, optional approved voice references, timing and subtitles.
10. Local render queue, resuming, resource preflight, VRAM budgeting, disk/cancel handling, per-shot progress.
11. Episode QA: character drift, wrong costume/face, speech mismatch, flicker, hand artifacts, story contradictions, black frames, audible clipping.
12. Exports: Facebook 9:16 + 16:9, series numbering, optional end card, captions, draft thumbnail and metadata.
13. Future optional plugin interfaces; never require external inference providers.

## Architecture and model API integration
- User story/source of truth → **deterministic non-destructive segmentation**, optional Ollama writer with strict JSON schema → series bible → episode manifest → shot manifest.
- Prompt compilation includes series style + canonical character IDs + episode events + camera/lighting and consistent seed/reference handles.
- **ComfyUI Workflow Adapter:** users export compatible ComfyUI workflow as **API-format JSON**, mark prompt insertion points with placeholders, app queues through POST /prompt, polls /history/{prompt_id}, downloads a completed generated **video** via /view; no remote proprietary API.
- Support cancel/retry, deterministic prompts, explicit clip provenance and model license; do not auto-retry forever.
- Renderer consumes real shot video assets or an **explicitly labeled** animatic / storyboard test mode. Missing assets should be visibly marked.
- Maintain storage schema for episode and scene versions; preserve original storyline untouched.

## Realistic hardware profiles
- **CPU-only 5600G + 16GB:** script, local small-LLM story planning (may be slow), JSON editing, media import, FFmpeg final assembly, some lightweight audio. No credible promise of satisfactory Wan/Hunyuan/LTX video diffusion generation speed.
- **8GB NVIDIA VRAM:** Wan 2.2 TI2V 5B ComfyUI native offloading *possible*, lower resolution/short clips, performance variable; not equivalent to full Flow quality.
- **14–16GB+ VRAM:** more model options such as Hunyuan 1.5 with offload; memory still tight.
- **24–32GB+ VRAM, high system RAM, generous SSD:** advanced LTX, longer shots and stronger continuity workflows.
- Cloud inference, even for openly licensed weights, is only free if you own/receive free compute. No guarantee.

## First development tranche vs future
**Build first:** editable series + episodes + canon + scene director, persistence, local model readiness, ComfyUI integration contract, FFmpeg assembly, clean desktop shell and tests.

**Then:** media manager with reference image upload, real templates for Wan, audio narration/captions aligned to footage, actual continuity checking, scene extensions, versioned non-destructive timeline, advanced render QA, benchmark per machine.

## Rights, safety and business
- Facebook [originality guidance (2026-03)](https://about.fb.com/news/2026/03/rewarding-original-creators-on-facebook/) favors original production over unoriginal or low-value repurposing; never promise monetization eligibility.
- User must own/license source stories, likenesses, voices, music and reference media. No voice-cloning someone else's identity without permission.
- Maintain asset provenance and license per generation (model, version, prompt, seed, human changes).
- Label synthetic media when required by platform context/policy. Provide editorial QA to catch incoherent or repetitive episodes.
